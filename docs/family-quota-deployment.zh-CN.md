# New API 家族额度部署手册

本仓库基于 QuantumNous/New API 的提交 [`b388140a`](https://github.com/QuantumNous/new-api/commit/b388140acfd80369ec6243b16869daff1b4051f4)。

## 升级已有站点

1. 确认站点当前版本。先在测试环境用生产库备份验证升级，尤其是从其他版本升级时。维护窗口内暂停家族渠道，并备份主库、日志库、Compose 配置和数据卷。使用 SQLite 时，应在停服后备份数据库，或用 SQLite 的备份命令取得一致快照。
2. 在部署主机上构建镜像。

   ```bash
   git clone https://github.com/whathill111/new-api-family-quota.git
   cd new-api-family-quota
   docker build -t new-api-family:local .
   ```

3. 在**原部署目录**修改已有的 New API 服务。以下片段展示需要合并的两项。保留已有环境变量、数据库连接、Redis、端口、反代、数据卷和会话密钥。移除该服务指向旧源码的 `build` 配置（如有）。

   ```yaml
   services:
     new-api:
       image: new-api-family:local
       environment:
         FAMILY_QUOTA_GROUP: "家族活动专属分组"
   ```

   如果原 `environment` 采用列表写法，追加一行 `- FAMILY_QUOTA_GROUP=家族活动专属分组`。值须与后台分组名完全一致。变量为空时家族额度功能关闭。每套站点可配置一个家族分组。

4. 停掉旧版应用节点。在原部署目录运行下列命令。应用的主节点启动时会创建三张家族额度表。多节点部署先启动主节点，等迁移完成后再启动其余节点，各节点统一使用新镜像和同一个分组名。

   ```bash
   docker compose stop new-api
   docker compose up -d --no-deps new-api
   docker compose logs --tail=100 new-api
   ```

5. 用站点最高权限管理员登录，打开「钱包」。确认「家族活动额度」卡片出现，完成下方验证后再开放家族渠道。

## 站点配置与使用

- 在计费设置中保存家族分组及所需倍率，例如 `0.05`。将专属渠道只绑定到家族分组。所有模型单价仍使用站点现有计费配置。
- 在「用户」中按 ID 找到成员，将其账号分组设为家族分组。若旧 API 密钥的分组原本留空，该密钥会继承新的账号分组。需要继续按原方式使用的旧密钥应显式选择原普通分组。家族密钥请选择家族分组。「自动」路由跳过家族分组。
- 在「钱包 → 家族活动额度」由最高权限管理员发放。填用户 ID 和额度可以直接到账。生成卡密时可绑定一个成员，或将 ID 留空批量生成可由任一家族成员兑换的卡密。额度金额按站点内部美元单位填写。
- 复制新生成的卡密后发给成员，每张只能兑换一次。原码只在生成时显示。成员登录后在「钱包 → 家族活动额度」输入卡密，可查看家族余额。
- 家族组的聊天调用按预估额度预扣，按实际用量结算。上游请求失败时释放预扣额度。家族组余额不足会拒绝新请求。普通余额、订阅余额与家族余额各自结算。API 密钥自身的用量限制仍然生效。
- 家族额度支持 Chat Completions、HTTP Responses、Messages 和站内游乐场的同步文本请求，包括流式响应。异步任务、图片、音频及 WebSocket 调用使用各自常规分组。

## 上线验证

用测试成员发一张小额卡密，核对家族余额增加。重复兑换同一张要失败。用非成员账号验证无法兑换。随后用家族密钥分别试一次流式和非流式文本请求，核对家族余额和密钥用量的变化。将测试成员家族余额耗尽后再发一个请求，确认服务拒绝调用且普通余额未被扣减。

预扣量基于请求估算。若已送出的请求最终费用高于估算，结算可能使**家族余额**为负，继续充值时会先抵扣这部分差额。对于异常退出时仍未结算的预扣，请核对上游与本站用量记录后处理，避免误退实际已产生的费用。预扣记录保存在 `family_quota_holds` 中，`finalized_at = 0` 表示未结算。

## 回滚

先停用家族渠道，再停止新应用节点。恢复原 Compose 配置和镜像后启动旧应用。这样可避免旧版把家族业务记入普通钱包。保留家族额度表及数据库备份，以便之后恢复功能。
